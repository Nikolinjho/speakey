# Локальная оценка распознавания

Стенд проверяет корпус и сравнивает расшифровки с подтверждёнными эталонами. `evaluate.py` оценивает готовые ответы, `runners.py` запускает локальный Whisper через проверочную сборку Speakey. Микрофон не используется, веса автоматически не скачиваются.

## Проверка стенда

Из корня проекта:

```bash
python3 -m unittest discover -s Tests/SpeechEvaluation -v
bash scripts/test-speech-diagnostics.sh
bash scripts/test-speech-export.sh
```

Тесты используют синтетический звук во временных каталогах. Их успех подтверждает работу стенда, но не качество распознавания речи.

## Корпус

Личные файлы находятся вне репозитория. JSONL содержит по одному объекту на строку:

```json
{"id":"clip-001","audio":"clip-001.wav","reference":"Проверь Nuxt, не Next.","reference_confirmed":true,"session_id":"day-01-morning","split":"train","critical_terms":["Nuxt","Next"]}
```

- `audio` – путь относительно JSONL или абсолютный путь. Нужен mono WAV, 16000 Hz: integer PCM 8/16/24/32 бит или IEEE Float32. Размер файла ограничен 256 MiB. Float32-сэмплы должны быть конечными.
- `reference` – то, что действительно произнесено. `reference_confirmed: true` ставится после проверки человеком.
- `session_id` – одна сессия записи. Она целиком относится к одной выборке.
- `split` – `train`, `dev` или `test`. Параметры подбираются по `dev`, итог измеряется по `test`.
- `critical_terms` – необязательные термины, присутствующие в эталоне. Их точные вхождения считаются отдельно с учётом регистра.
- `edited_text` – необязательный желаемый вариант оформления. В расчёте точности распознавания не используется.
- `kind: "silence"` – запись тишины с пустым `reference`. Непустой ответ модели считается ложным распознаванием.
- `duration_seconds` – необязательная контрольная длительность.

Проверка отклоняет повторяющиеся ID, неподтверждённые эталоны, повреждённый WAV и пересечение сессий, одинакового PCM или нормализованных эталонов между выборками. Похожие фразы также отклоняются между выборками: минимум 8 нормализованных слов в каждой фразе и расстояние Левенштейна по словам не больше 12,5% длины более длинной фразы. Это проверка близких формулировок, а не смысла. Одинаковые короткие фразы нужно держать в одной выборке.

```bash
python3 Tools/SpeechEvaluation/evaluate.py validate /private/tmp/speech-corpus/manifest.jsonl
```

`/private/tmp` подходит для синтетического примера, но может очищаться. Для личного корпуса требуется постоянное защищённое хранилище. Этот CLI не шифрует исходный WAV и JSONL. Не экспортируй личные записи в открытом виде без необходимости.

## Готовые расшифровки

Отдельный JSONL для одного движка/варианта настроек:

```json
{"id":"clip-001","hypothesis":"Проверь Next, не Next."}
```

В файле должны быть ровно ID выбранной выборки, без пропусков и повторов. По умолчанию оценивается `test`.

```bash
python3 Tools/SpeechEvaluation/evaluate.py evaluate \
  /private/tmp/speech-corpus/manifest.jsonl \
  /private/tmp/speech-corpus/turbo-hypotheses.jsonl \
  --split train \
  --output /private/tmp/speech-corpus/turbo-train-report.json
```

Отчёт создаётся только новым файлом вне репозитория с правами `0600`. Он содержит счётчики и ID, без текста расшифровок. В stdout выводятся только агрегированные показатели. Для готовых сторонних гипотез отдельно сохраняй версию модели, хеш весов, параметры, устройство и условия запуска. Встроенный `runners.py` формирует протокол своего прогона автоматически.

WER учитывает замены, пропуски и добавления слов. CER считает ошибки символов, включая нормализованные пробелы. Правила нормализации сохранены в отчёте. Числа не превращаются в слова, отрицания не удаляются. Лексический WER не оценивает смысл или качество пунктуации. Точный счётчик терминов проверяет их наличие, но не доказывает, что термин стоит в правильном месте.

## Экспорт диагностической записи

Для команды нужна новая проверочная сборка, в которой реализован CLI. Установленная старая Speakey этот режим не поддерживает. Не запускай старую версию с этими параметрами.

```bash
SPEAKEY_SPEECH_CLI=1 /private/tmp/Speakey_speech_evaluation.app/Contents/MacOS/Speakey \
  export --input /path/to/record.enc --output /path/to/new-export-directory
```

Команда читает существующий ключ диагностики из Keychain без диалога. Она не создаёт и не заменяет ключ. При отказе доступа экспорт завершится ошибкой. Реальный доступ установленного приложения к ключу требует отдельной проверки.

В новом каталоге с правами `0700` появятся `audio.wav`, `trace.json` и `manifest.jsonl` с правами `0600`. Это явный экспорт в открытом виде, включая текст и голос. Float32 WAV сохраняет биты входа модели без перекодирования в PCM16. Существующий каталог не перезаписывается.

В черновике `reference_confirmed` выключен, а `reference` пустой. Прослушай запись, впиши дословный эталон, укажи сессию и выборку. Включай подтверждение только после проверки. Модель не создаёт сама себе правильные ответы.

## Повторное распознавание корпуса

```bash
python3 Tools/SpeechEvaluation/runners.py /path/to/manifest.jsonl \
  --executable /private/tmp/Speakey_speech_evaluation.app/Contents/MacOS/Speakey \
  --model /path/to/ggml-large-v3-turbo.bin \
  --language ru --split test --stage raw \
  --output /path/to/new-turbo-run
```

Нужен уже существующий локальный файл GGML. Веса не скачиваются. Выбранная часть корпуса должна иметь подтверждённые эталоны. Прогон создаёт новый приватный каталог вне репозитория, содержащий `hypotheses.jsonl` и `run.json`. Гипотезы можно передать `evaluate.py`.

`--stage raw` оценивает текст модели до удаления эха подсказки. `--stage echo-cleaned` выбирает результат после удаления эха. Словарь замен, фильтр фраз и настройки оформления VoiceController в этом режиме не применяются. Личный словарь явно отключён. Поэтому такой прогон не является полным повторением текущей пользовательской диктовки.

Протокол сохраняет хеши executable, весов, корпуса, WAV и полной конфигурации, включая хеш подсказки. Проверяются изменения входов во время прогона. Для каждого клипа запускается отдельный процесс. Время процесса включает загрузку модели, это не измерение повторной диктовки с уже загруженными весами. Время самого декодирования записывается отдельно. Все ошибки завершают прогон, частичный каталог удаляется. Таймаут завершает только созданный дочерний процесс.

WhisperBridge использует существующий системный механизм логирования Speakey с метаданными. Runner подавляет stdout/stderr дочернего процесса, но не меняет обычное файловое логирование приложения. В режиме CLI не запускаются AppDelegate, микрофон и наблюдение за вводом.

Qwen, Parakeet и обучение весов этим runner пока не поддерживаются. Проверка на синтетической речи подтверждает запуск, но не качество на голосе пользователя.
