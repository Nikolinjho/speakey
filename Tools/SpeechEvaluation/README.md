# Локальная оценка распознавания

Стенд сравнивает расшифровки с подтверждёнными эталонами. `evaluate.py` оценивает готовые ответы, `runners.py` запускает Whisper, Parakeet v3 или опциональный Qwen3-ASR на локальных весах. Whisper и Parakeet используют проверочную сборку Speakey, Qwen – отдельный Python-процесс. При повторном распознавании микрофон не используется, веса не скачиваются.

## Проверка стенда

Из корня проекта:

```bash
python3 -m unittest discover -s Tests/SpeechEvaluation -v
bash scripts/test-speech-diagnostics.sh
bash scripts/test-speech-export.sh
bash scripts/test-speech-review.sh
```

Тесты используют синтетический звук во временных каталогах. Их успех подтверждает работу стенда, но не качество распознавания речи.

## Корпус

Личные файлы находятся вне репозитория. JSONL содержит по одному объекту на строку:

```json
{"id":"clip-001","audio":"clip-001.wav","reference":"Проверь Nuxt, не Next.","reference_confirmed":true,"session_id":"day-01-morning","split":"train","critical_terms":["Nuxt","Next"]}
```

- `audio` – путь относительно JSONL или абсолютный путь. Нужен mono WAV, 16000 Hz: integer PCM 8/16/24/32 бит или IEEE Float32. Размер файла ограничен 256 MiB. Float32-сэмплы должны быть конечными.
- `reference` – то, что действительно произнесено. `reference_confirmed: true` ставится после проверки человеком.
- `session_id` – одна сессия записи. Она целиком относится к одной выборке.
- `split` – `train`, `dev` или `test`. Параметры подбираются по `dev`, итог измеряется по `test`.
- `critical_terms` – необязательные термины, присутствующие в эталоне. Их точные вхождения считаются отдельно с учётом регистра.
- `edited_text` – необязательный желаемый вариант оформления. В расчёте точности распознавания не используется.
- `kind: "silence"` – запись тишины с пустым `reference`. Непустой ответ модели считается ложным распознаванием.
- `duration_seconds` – необязательная контрольная длительность.

Проверка отклоняет повторяющиеся ID, неподтверждённые эталоны, повреждённый WAV и пересечение сессий, одинакового PCM или нормализованных эталонов между выборками. Похожие фразы также отклоняются между выборками: минимум 8 нормализованных слов в каждой фразе и расстояние Левенштейна по словам не больше 12,5% длины более длинной фразы. Это проверка близких формулировок, а не смысла. Одинаковые короткие фразы нужно держать в одной выборке.

```bash
python3 Tools/SpeechEvaluation/evaluate.py validate /private/tmp/speech-corpus/manifest.jsonl
```

`/private/tmp` подходит для синтетического примера, но может очищаться. Для личного корпуса требуется постоянное защищённое хранилище. Этот CLI не шифрует исходный WAV и JSONL. Не экспортируй личные записи в открытом виде без необходимости.

## Готовые расшифровки

Отдельный JSONL для одного движка/варианта настроек:

```json
{"id":"clip-001","hypothesis":"Проверь Next, не Next."}
```

В файле должны быть ровно ID выбранной выборки, без пропусков и повторов. По умолчанию оценивается `test`.

```bash
python3 Tools/SpeechEvaluation/evaluate.py evaluate \
  /private/tmp/speech-corpus/manifest.jsonl \
  /private/tmp/speech-corpus/turbo-hypotheses.jsonl \
  --split train \
  --output /private/tmp/speech-corpus/turbo-train-report.json
```

Отчёт создаётся только новым файлом вне репозитория с правами `0600`. Он содержит счётчики и ID, без текста расшифровок. В stdout выводятся только агрегированные показатели. Для готовых сторонних гипотез отдельно сохраняй версию модели, хеш весов, параметры, устройство и условия запуска. Встроенный `runners.py` формирует протокол своего прогона автоматически.

WER учитывает замены, пропуски и добавления слов. CER считает ошибки символов, включая нормализованные пробелы. Правила нормализации сохранены в отчёте. Числа не превращаются в слова, отрицания не удаляются. Лексический WER не оценивает смысл или качество пунктуации. Точный счётчик терминов проверяет их наличие, но не доказывает, что термин стоит в правильном месте.

## Сбор примеров в приложении

В настройках голоса есть переключатель «Собирать примеры распознавания». По умолчанию сбор выключен. После явного включения обычные пакетные диктовки сохраняют точный Float32-вход распознавания и промежуточные тексты в зашифрованном виде отдельно от истории. Данные остаются на Mac. Совместимый способ включения перед запуском – `SPEAKEY_SPEECH_DIAGNOSTICS=1`. Явное выключение в UI имеет приоритет над этой переменной.

Выключение отменяет сохранение незавершённых записей. Повторное включение не восстанавливает отозванное согласие. Уже собранные примеры остаются. Хранятся не более 200 примеров за 7 дней, старые удаляются при следующем сохранении.

Кнопка «Удалить собранные примеры…» выключает сбор и удаляет его записи после подтверждения. Подтверждённые правки тоже удаляются. История диктовок, ключ шифрования и ранее экспортированные файлы сохраняются. Сбор примеров сам по себе не обучает модель.

## Экспорт диагностической записи

Для команды нужна новая проверочная сборка, в которой реализован CLI. Установленная старая Speakey этот режим не поддерживает. Не запускай старую версию с этими параметрами.

```bash
SPEAKEY_SPEECH_CLI=1 /private/tmp/Speakey_speech_evaluation.app/Contents/MacOS/Speakey \
  export --input /path/to/record.enc --output /path/to/new-export-directory
```

Команда читает существующий ключ диагностики из Keychain без диалога. Она не создаёт и не заменяет ключ. При отказе доступа экспорт завершится ошибкой. Реальный доступ установленного приложения к ключу требует отдельной проверки.

В новом каталоге с правами `0700` появятся `audio.wav`, `trace.json` и `manifest.jsonl` с правами `0600`. Это явный экспорт в открытом виде, включая текст и голос. Float32 WAV сохраняет биты входа модели без перекодирования в PCM16. Существующий каталог не перезаписывается.

В черновике `reference_confirmed` выключен, а `reference` пустой. Такой файл нельзя оценивать или передавать runner до ручной проверки.

## Подтверждение эталона

В проверочной сборке доступно окно «Проверить расшифровки…» из настроек сбора. Оно позволяет прослушать пример, вписать дословный эталон, отдельно задать оформление и подтвердить сессию с выборкой. Подтверждения хранятся зашифрованными. Экспорт WAV и JSONL выполняется только явной командой в окне. [Порядок работы и физические проверки](../../docs/development/speech-corpus-review.md).

CLI остаётся доступным для уже экспортированного черновика.

Прослушай запись и сохрани дословный текст в отдельном UTF-8-файле. Команда читает этот файл, а не ответ модели:

```bash
python3 -m Tools.SpeechEvaluation.corrections /path/to/export/manifest.jsonl \
  --reference-file /path/to/reference.txt \
  --session-id day-01-morning --split train \
  --output /path/to/confirmed.jsonl
```

Команда создаёт новый JSONL вне репозитория с правами `0600`, ставит `reference_confirmed: true` и сохраняет хеш исходного черновика. Существующий файл не перезаписывается, исходный черновик не меняется. Для подтверждённой тишины нужен пустой файл эталона и явный `--silence`. Желаемое оформление можно передать через `--edited-file /path/to/edited.txt`. Оно попадёт в отдельное поле `edited_text` и не заменит дословный эталон.

## Повторное распознавание корпуса

Все команды ниже выполняются из корня проекта. Выбранная часть корпуса должна иметь подтверждённые эталоны. Каждый прогон создаёт новый каталог вне репозитория с правами `0700`, содержащий `hypotheses.jsonl` и `run.json` с правами `0600`. Гипотезы можно передать `evaluate.py`.

### Whisper

Нужен существующий локальный файл GGML и проверочная сборка Speakey с CLI:

```bash
python3 -m Tools.SpeechEvaluation.runners /path/to/manifest.jsonl \
  --engine whisper \
  --executable /private/tmp/Speakey_speech_evaluation.app/Contents/MacOS/Speakey \
  --model /path/to/ggml-large-v3-turbo.bin \
  --language ru --split test --stage raw \
  --output /path/to/new-turbo-run
```

Whisper остаётся движком по умолчанию. `--stage raw` выбирает текст модели до удаления эха подсказки, `--stage echo-cleaned` – результат после удаления эха.

### Parakeet v3

Нужны Apple Silicon, проверочная сборка с FluidAudio и существующий каталог `parakeet-tdt-0.6b-v3`. Имя каталога соответствует `Repo.parakeetV3.folderName` подключённой FluidAudio. Суффикс `-coreml` в имени репозитория не является именем локального каталога загрузчика.

```bash
python3 -m Tools.SpeechEvaluation.runners /path/to/manifest.jsonl \
  --engine parakeet \
  --executable /private/tmp/Speakey_speech_evaluation.app/Contents/MacOS/Speakey \
  --model /path/to/parakeet-tdt-0.6b-v3 \
  --language ru --split test --stage raw \
  --output /path/to/new-parakeet-run
```

Native CLI также принимает `SPEAKEY_SPEECH_CLI=1 … transcribe --engine parakeet --input … --model … --language ru --output …`. Он создаёт отдельный менеджер, включает офлайн-режим FluidAudio и использует v3 int8 с `melChunkContext=false`. Данные модели проверяются до загрузки, после неё и после распознавания. Хеш охватывает обычные файлы загружаемых компонентов `Preprocessor.mlmodelc`, `Encoder.mlmodelc`, `Decoder.mlmodelc`, `JointDecisionv3.mlmodelc` и `parakeet_vocab.json`. Симлинки, специальные файлы и не-ASCII-пути запрещены.

`ru` и `en` задают фильтр письменности, а не выбор языка модели. `auto` отключает фильтр. Возвращается текст FluidAudio до исправлений Speakey. Для Parakeet оба значения `--stage` выбирают один и тот же результат.

### Опциональный Qwen3-ASR

Окружение Qwen предназначено только для локальной оценки. Текущий набор зависимостей требует macOS 26+, Apple Silicon и Homebrew Python 3.12 по пути `/opt/homebrew/bin/python3.12`. Это ограничение отдельного стенда Qwen, а не основного приложения Speakey.

План подготовки без установки и загрузки:

```bash
python3 scripts/setup-speech-qwen.py --plan
```

Подготовка `vendor/speech-evaluation/venv` устанавливает версии из `Tools/SpeechEvaluation/requirements-qwen.lock`. Список установленных пакетов сохраняется в `vendor/speech-evaluation/requirements-installed.txt`:

```bash
python3 scripts/setup-speech-qwen.py
```

По умолчанию эта команда устанавливает зависимости из PyPI, но не скачивает модель. Только явный флаг разрешает получение весов:

```bash
python3 scripts/setup-speech-qwen.py --download-model
```

Загружается публичная `mlx-community/Qwen3-ASR-1.7B-8bit`, закреплённая на commit `a8379a2e2f9e313c9292cdf1af4055ab56d50d55`. Размеры и хеши файлов проверяются по `qwen_assets.py`, независимо от локального манифеста. Веса появляются в `vendor/speech-evaluation/models/qwen3-asr-1.7b-8bit`, существующая модель проверяется без перезаписи. `vendor/` исключён из Git.

Проверка локальной модели и версий окружения:

```bash
vendor/speech-evaluation/venv/bin/python -m Tools.SpeechEvaluation.qwen preflight \
  --model "$PWD/vendor/speech-evaluation/models/qwen3-asr-1.7b-8bit"
```

Прогон корпуса использует Python именно этого venv:

```bash
python3 -m Tools.SpeechEvaluation.runners /path/to/manifest.jsonl \
  --engine qwen \
  --executable vendor/speech-evaluation/venv/bin/python \
  --model "$PWD/vendor/speech-evaluation/models/qwen3-asr-1.7b-8bit" \
  --language ru --split test --stage raw --timeout 300 \
  --output /path/to/new-qwen-run
```

Для отдельного WAV доступна команда:

```bash
vendor/speech-evaluation/venv/bin/python -m Tools.SpeechEvaluation.qwen transcribe \
  --input /path/to/audio.wav \
  --model "$PWD/vendor/speech-evaluation/models/qwen3-asr-1.7b-8bit" \
  --language ru --output /path/to/new-qwen-result.json
```

Qwen загружает только проверенные локальные файлы. Hugging Face работает в офлайн-режиме, сетевые Python-сокеты блокируются на время загрузки и распознавания. Это программное ограничение внутри Python-процесса, а не системный межсетевой экран. Remote code, личные подсказки и hotwords отключены. Ответ Qwen уже нормализован библиотекой MLX Audio. Он записывается в `raw_hypothesis` и `hypothesis` с явным указанием этой границы обработки, оба значения `--stage` дают одинаковый текст.

## Протокол и границы проверки

Протокол сохраняет хеши executable, весов, корпуса, WAV и конфигурации, включая хеш подсказки. Для Qwen дополнительно сохраняется хеш Python-модуля. Проверяются изменения входов во время прогона. Для каждого клипа запускается отдельный процесс. Его время включает загрузку модели, время декодирования записывается отдельно. Это не измерение повторной диктовки с уже загруженными весами. Ошибка прерывает прогон и удаляет частичный каталог. Таймаут завершает созданный дочерний процесс.

Словарь замен, фильтр фраз и настройки оформления VoiceController в CLI не применяются. Личный словарь отключён. Поэтому прогон не повторяет весь пользовательский путь диктовки. Native CLI запускается до AppDelegate, микрофона и наблюдения за вводом. Он сохраняет существующее файловое логирование метаданных Speakey, runner подавляет stdout/stderr дочернего процесса.

Стенд не обучает веса и не подтверждает улучшение качества на голосе пользователя. Для такого вывода нужен личный корпус с проверенными эталонами и отдельной итоговой выборкой. Синтетические тесты подтверждают устройство стенда, а не точность движков.
