# Открытие настроек Keyboop

27 октября 2026 года, MSK.

## Причина

Вызов `SettingsWindowController()` из AppDelegate выбирал унаследованный конструктор `NSWindowController`, создающий контроллер без окна. При добавлении RightLayout прежний конструктор без параметров заменили на `init(neuralPresentation: ... = .shared)`. Значение параметра по умолчанию не отменяет выбор унаследованной перегрузки.

Приложение продолжало обрабатывать ввод, но пункт меню и повторный запуск не показывали настройки. Старые проверки интерфейса явно передавали `neuralPresentation` и проходили по другому пути.

## Исправление и проверка

Восстановлен явный конструктор без параметров, который передаёт общее хранилище в конструктор с параметром. В нативную проверку добавлен тот же вызов, что используется при обычном открытии настроек. Проверка требует настоящее окно с контроллером содержимого.

До исправления полная сборка завершила проверку с кодом 1: `FAIL: Обычный конструктор настроек создаёт окно`. Исправленная полная сборка прошла 12 нативных проверок без ошибок в светлой и тёмной теме. Строгая подпись проверена, код 0. [До исправления](artifacts/settings-opening/red.txt), [после, тёмная тема](artifacts/settings-opening/green-dark.txt), [светлая тема](artifacts/settings-opening/green-light.txt).
