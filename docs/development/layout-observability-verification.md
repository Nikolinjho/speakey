# Проверка постоянного журнала раскладки

27 октября 2026, MSK. Ветка `feat/layout-diagnostics`.

Журнал по умолчанию открывает сохранённые решения. Они содержат исходный токен,
альтернативу из Keymap, фактическое совпадение со словарями, причину решения,
действие и результат отправки замены. Отсутствие слова в словарях – отдельный
факт, а не объяснение причины решения детектора. Например, для `дд` альтернатива
`ll` есть в английском словаре, а для `жжжж` обе формы отсутствуют.

Старое решение можно отметить после перезапуска. Удаление и перепечатывание
пропущенного слова создаёт кандидата ошибки. Подтверждение кандидата и применение
правила остаются отдельными действиями. Сбор наблюдений не включает автоматическое
обучение детектора.

## Воспроизводимые проверки

```bash
bash scripts/test-layout-diagnostics.sh all
bash scripts/test-layout-detector.sh all
bash scripts/test-layout-baseline-contracts.sh
KEYBOOP_SIGN_ID=- KEYBOOP_BUILD_APP="$PWD/Keyboop_local.app" bash build-app.sh
KEYBOOP_JOURNAL_PREVIEW=1 KEYBOOP_JOURNAL_PREVIEW_CHECK=1 KEYBOOP_UPDATER=1 \
  ./Keyboop_local.app/Contents/MacOS/Keyboop
```

Чистые тесты: 252 проверки журнала и 57 проверок настоящего детектора, 0 ошибок.
Логи: `logs/layout-observability-diagnostics.log`,
`logs/layout-observability-detector.log`, `logs/layout-observability-contracts.log`.

Нативная проверка использует настоящие AppKit-контролы: поток решений по умолчанию,
фильтр словаря, поле ожидаемого результата и кнопку отметки. Решение старше
10 секунд читается заново с диска без ожидания таймера. Повторная отметка сохраняет
один кейс. Проверка пропуска `дд` использует настоящий KeystrokeBuffer, удаление,
Keymap и перепечатывание `ll`, затем проверяет сохранённое наблюдение и свидетельство
ошибки. Прежние проверки подтверждения, применения и удаления правил, выключения
сбора и модальной очистки сохранены. Очистка удаляет наблюдения и кейсы,
сохраняя квитанцию активного правила до отдельного удаления.

Preview входит до AppDelegate и системных guard, использует отдельные UserDefaults,
временное хранилище и backend правил. Он не запускает второй перехватчик клавиатуры
и не изменяет данные установленного приложения. Это проверка реального окна
и компонентов, а не сквозная проверка физического ввода через Accessibility
или поведения Secure Input.

Первый нативный прогон выявил неверное ожидание в проверочном наборе: `ll` уже есть
в английском словаре. Лог: `logs/layout-observability-native-fixture-red.log`.
Для фильтра отсутствия обоих слов используется отдельный реальный пример `жжжж`.

Финальный нативный прогон: **29 проверок, 0 ошибок**, exit 0.
Лог: `logs/layout-observability-native.log`. Полная сборка завершилась с exit 0,
`codesign --verify --deep --strict Keyboop_local.app` – exit 0.
Лог сборки: `logs/layout-observability-build.log`.
