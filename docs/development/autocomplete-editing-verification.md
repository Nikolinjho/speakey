# Редактирование и выбор слов

13 ноября 2026 года, MSK. Локальная ветка `feat/autocomplete`.

Добавлены четыре функции:

- Дописывание только начатого слова. Пробел и следующее слово не добавляются.
- Вставка внутри строки с сохранением текста справа. Предпросмотр располагается под кареткой.
- До пяти альтернатив продолжения. Выбор цифрой, стрелками с Enter или по Tab, отмена по Esc.
- Синонимы выделенного слова или короткой фразы. Модель учитывает соседний текст, принятие заменяет только исходное выделение.

Переключатели находятся в «Автодополнение → Редактирование и варианты». Автоматические списки включаются отдельно, задержка настраивается. Команды ручного вызова назначаются в разделе сочетаний. Новые режимы выключены по умолчанию, новые команды не занимают сочетания сами.

## Живой прогон

В TextEdit проверены:

- Назначение команды синонимов через окно записи сочетаний.
- `This is a good result.`: цифра 1 заменила только `good` на `excellent`.
- `This is a result.`: стрелка вниз и Enter вставили альтернативу `bad` перед `result.`.
- В том же пропуске Tab принял обычное продолжение `great`. Сохранённый файл содержит ровно `This is a great result.`.
- В режиме текущего слова Tab превратил `Спасибо за вним` в `Спасибо за внимательное`. Сохранённый файл не содержит пробела после слова, хотя общая настройка добавления пробела включена.

В Safari проверены ручной вызов списка, автоматические варианты после паузы, автоматические синонимы после устойчивого выделения и отмена по Esc. Вставка варианта цифрой сохранила `result.` справа. Tab в обычном предпросмотре превратил `This is a result.` в `This is a bad result.`. Затем ручной вызов синонимов и цифра 1 заменили только `bad` на `poor`.

Safari получает Unicode-события в конкретный PID. После каждой части длиной до 20 UTF16 единиц проверяется, что текст появился в том же поле и соседний текст сохранён. Смена фокуса останавливает отправку оставшихся частей. После неопределённого результата повторной вставки нет.

Повторный запуск для открытия настроек сохранил PID помощника, локальный `/health` вернул `HTTP/1.1 200 OK` до и после запуска.

Тестовые сочетания `Control+Option` не доходили до окна записи в текущем окружении. Для прогона использованы `Control+Command+J/K/L`. После проверки временные настройки восстанавливаются.

## Найденные и исправленные ошибки

- Пунктуация вставки могла склеиться со словом справа.
- Пропадал обязательный пробел справа при превращении вставки в вариант одного слова.
- Ответ без начального пробела мог склеиться со словом слева.
- После ручного допечатывания части вставки оставалась старая цель AX.
- Режим одного слова мог добавлять пробел из общей настройки принятия.
- При AX-записи в собственное окно AppKit зависал из-за записи с фоновой очереди. Обращения к собственному PID перенесены на главный поток.
- Вторичный запуск Speakey для открытия настроек удалял сокет работающего помощника. Очистка теперь проверяет владение по PID. Регрессионный тест сначала воспроизвёл ошибку, затем прошёл с исправлением.

Перед показом и принятием новых предложений проверяются PID, AX-элемент, UTF16-диапазон и текст по обе стороны выделения. Устаревший результат не вставляется. После неоднозначного AX-ответа повторной печати через буфер обмена нет. Поля Gecko отклоняются при принятии этих режимов. Прежний обычный режим сохраняет свой TextReplacer для совместимости с приложениями без AX-записи.

## Ограничения качества

Список синонимов не исправляет согласование за пределами выделения: при замене `good` на `excellent` артикль `a` остаётся исходным. Маленькая base-модель иногда предлагает неподходящее завершение или пустой список. Например, вариант `París` не прошёл словарный фильтр в английском контексте. Такие ответы не принимаются автоматически.

Доменные правила исключены из задачи. Терминалы остаются выключены.
