# Проверка микрофона

В блоке «Микрофон» настроек голоса есть кнопка проверки. Она включает прямое воспроизведение выбранного микрофона на текущем системном выходе. Повторное нажатие останавливает проверку. Для прослушивания лучше использовать наушники, чтобы звук динамиков не возвращался в микрофон.

Проверка не создаёт записи, не сохраняет звук, не запускает распознавание и не включает сбор примеров. Доступ к микрофону запрашивается только при явном нажатии кнопки. Системная громкость и выбор устройств не меняются.

Проверка останавливается при смене микрофона, уходе из раздела голоса, закрытии настроек, сне системы и запуске обычной диктовки. Отмена во время запроса разрешения или запуска не должна приводить к запоздалому воспроизведению.

Звук идёт через `AVCaptureDeviceInput` и `AVCaptureAudioPreviewOutput` в отдельной `AVCaptureSession`. Буферы не передаются в `AudioRecorder`, модели или историю. Старт и остановка сессии выполняются вне главного потока. Задержка зависит от устройств, особенно при Bluetooth-подключении.

## Физическая проверка

Эти действия выполняются пользователем, автоматические проверки не открывают микрофон:

- Выбрать нужный микрофон, подключить наушники и включить проверку. Речь должна быть слышна на системном выходе.
- Остановить проверку, звук должен прекратиться. Повторить быстрый запуск и отмену.
- Уйти в другой раздел, закрыть настройки и сменить микрофон. Проверка должна остановиться в каждом случае.
- Начать обычную диктовку при включённой проверке. Прямое воспроизведение должно прекратиться, диктовка работает обычным способом.
- Отключить выбранное устройство или запретить доступ к микрофону. Интерфейс должен показать отказ, не переключаясь незаметно на другой выбранный вход.

## Автоматические проверки

`bash scripts/test-microphone-monitor.sh` завершился с кодом `0`: проверены отмена запроса разрешения, запоздалый запуск, передача выбранного входа, отказы и остановка. Проверка использует подставной вывод звука и не создаёт нативную сессию. Сам адаптер AVCapture компилируется вместе с тестами.

Полная проверка типов Swift с настоящими SDK, Whisper и FluidAudio завершилась с кодом `0`. Независимая проверка требований и отдельная проверка качества кода пройдены. Реальное воспроизведение через устройства ввода и вывода этими проверками не подтверждается, для него нужен физический пилот выше.

## Диагностика отсутствия звука

После сообщения пользователя о тишине добавлены индикатор уровня входа и проверка подключения. Уровень берётся из `AVCaptureAudioChannel.averagePowerLevel` с частотой четыре раза в секунду. Аудиобуферы не читаются и не сохраняются. Остановка очищает индикатор, запоздалые события отменённого запуска игнорируются.

Системный журнал получает сообщения с префиксом `[SpeakeyMicrophoneCheck]`: состояние соединения, число каналов, громкость preview, максимальный нормализованный уровень, домен и код системной ошибки. Имена устройств, аудио и тексты туда не добавляются.

Журналы первоначальных попыток показали открытие выбранных устройств без явной ошибки. Точная причина тишины пока не подтверждена. Даже активное соединение и ненулевой уровень не доказывают слышимый выход. Нужен повтор пользователем с наблюдением индикатора, затем сопоставление с техническим журналом.
