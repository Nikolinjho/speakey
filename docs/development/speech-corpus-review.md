# Подтверждение примеров речи

В проверочной сборке Speakey подготовка корпуса доступна из настроек голоса, рядом с управлением сбором примеров. Сбор по умолчанию выключен. Окно работает с диагностическими записями, а не с историей диктовок.

## Подготовка данных

1. Явно включи сбор и используй обычную диктовку. Для первой проверки нужны 30–50 фраз, включая случаи ошибок. При завершении пилота выключи сбор.
2. Открой просмотр собранных примеров. Список содержит время создания в MSK и ID. В карточке выбранной записи показаны дата и время с точностью до секунды. Звук и текст расшифровываются при выборе записи.
3. Прослушай пример и впиши то, что действительно произнесено. Новый эталон изначально пуст. Исходные ответы движков показаны отдельно и не считаются правильными автоматически.
4. Желаемое оформление при необходимости укажи в отдельном поле. Смысл, числа, имена и отрицания в дословном эталоне должны соответствовать записи.
5. Для пустого эталона явно подтверди тишину. Время создания определяется автоматически. Сессию и назначение примера выбирать не нужно.
6. Сохрани подтверждение. В списке появится зелёная отметка «Правка сохранена», у неподтверждённых примеров остаётся «Без правки». Отметка обновляется после сохранения и удаления, сохраняется при повторном открытии окна. Подтверждение можно пересмотреть или удалить. Это ещё не изменение словаря или обучение весов.
7. Явно экспортируй подтверждённый корпус в постоянное защищённое место вне Git-репозитория. Экспорт создаёт новый каталог с WAV и `manifest.jsonl`. Эти файлы уже не зашифрованы.

Срок хранения исходной диагностики – семь дней и не более 200 записей. Очистка происходит при следующем сохранении диагностики. Подтверждение не продлевает срок хранения звука. Экспорт нужен до истечения срока. Если исходник уже удалён, экспорт завершится ошибкой, а не пропустит запись незаметно. Отдельная кнопка позволяет явно удалить подтверждения без исходного звука, сохранив подтверждения с доступными исходниками.

Кнопка удаления собранных примеров выключает сбор и удаляет исходники вместе с подтверждениями. История диктовок, ключ Keychain и ранее экспортированные файлы сохраняются. Для исправления одной записи используй удаление её подтверждения в окне просмотра.

## Хранение

Диагностика находится в `~/Library/Application Support/Speakey/speech-diagnostics`, подтверждения – в соседнем `speech-corrections`. Обе группы файлов зашифрованы AES-GCM отдельным диагностическим ключом. Просмотр использует только существующий ключ и не создаёт новый при отказе доступа. Прослушивание создаёт WAV в памяти, без открытого временного файла.

Экспорт содержит только подтверждённые записи и точный Float32-вход движка. В JSONL сохраняются дословный эталон, оформление, время создания `created_at` с часовым поясом, служебная группа и хеши происхождения. Каталог получает права `0700`, файлы – `0600`. Существующая цель не перезаписывается, частичный экспорт удаляется при ошибке.

При первом подтверждении время создания исходного диагностического файла сохраняется внутри зашифрованной правки. Повторные исправления его не меняют. Новые примеры автоматически объединяются по календарному дню MSK в `session_id` вида `recorded-2026-11-02` и получают служебную выборку `dev`. У ранее сохранённых правок остаются прежние сессии и выборки. Подготовка отдельных `train` и `test` выполняется при сравнении моделей, без ручного выбора в окне исправлений. Подтверждение само по себе не обучает модель.

## Проверка корпуса и сравнение моделей

Из корня проекта:

```bash
python3 Tools/SpeechEvaluation/evaluate.py validate /path/to/export/manifest.jsonl
```

Дополнительная проверка отклоняет одинаковый звук и близкие формулировки, оказавшиеся в разных выборках. При подготовке сравнения дни записи разделяются целиком. Выборка `test` остаётся для итоговой проверки после подбора параметров на `dev`. Автоматическое сохранение всех новых примеров в `dev` ещё не создаёт независимую итоговую выборку. Команды запуска Turbo, Parakeet и Qwen приведены в [инструкции стенда](../../Tools/SpeechEvaluation/README.md).

## Физический пилот

Эти проверки требуют взаимодействия с приложением и реальной диктовки. Они не заменяются синтетическими тестами хранилища:

- Убедиться, что при выключенном сборе новый пример не появляется.
- Включить сбор, произнести фразу, выбрать её и проверить соответствие звука и исходного ответа.
- Быстро переключить выбранный пример во время загрузки и прослушивания. Звук предыдущего примера должен остановиться, его данные не должны заполнить новый.
- Подтвердить дословный текст, закрыть и открыть окно, проверить сохранённый эталон. Изменить оформление отдельно и убедиться, что эталон не поменялся.
- Проверить сохранение без выбора сессии и назначения. При повторном исправлении дата создания остаётся прежней. Пустой эталон без признака тишины не сохраняется.
- Экспортировать корпус, выполнить проверку JSONL и затем сравнение моделей.
- Удалить собранные примеры и убедиться, что окно пусто, сбор выключен, ранее экспортированный корпус остался.

Личные записи, включение микрофона и выдача диагностического ключа реальным установленным приложением в автоматических проверках этого прохода не использовались.

## Автоматические проверки

`bash scripts/test-speech-review.sh` проверяет зашифрованное сохранение и пересмотр эталона, запрет пересечения сессий между выборками, WAV без потерь, права файлов, опасные пути, неверные схемы, ограничение размера, явную тишину, очистку подтверждений без исходника и откат частичного экспорта. Два настоящих экспорта из Swift затем проходят `evaluate.py validate` в Python: по одному синтетическому примеру речи и тишины, оба `valid: true`.

Независимые проверки требований и качества кода завершены. Полная проверка типов Swift с подключёнными Whisper и FluidAudio завершилась с кодом `0`. Взаимодействие с окном на личных примерах и физический пилот остаются отдельной проверкой.
