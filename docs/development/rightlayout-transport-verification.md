# Системная доставка маркера и замена текста RightLayout

Проверка от 27.10.2026, окончательный результат сохранён в 16:12 MSK. Исходная ветка `feat/layout-diagnostics`, checkpoint `9d58fbb`. Проверочный процесс запускается через `KEYBOOP_NEURAL_TRANSPORT_CHECK=1` до `AppDelegate` и `Engine`.

## Что проверяется

Глобальная проба отправляет только непечатающий `keyDown/255` через `cghidEventTap`. Временный перехватчик на `cgSessionEventTap` передаёт в настоящий `EventTap.handle` только событие собственного PID с полным случайным 64-битным маркером текущего запуска. Проверяются доставка через ОС, сохранность токена и поглощение события.

Независимая проба отправляет маркер только собственному PID. Перехватчик процесса вызывает настоящий `TextReplacer.replaceInline(deleteCount: 6, with: "привет")` с `tapPostEvent`. Второй перехватчик того же PID получает события ниже точки `tapPostEvent`, сохраняет их копии и поглощает только собственную синтетику. Проверяются 14 отправленных и доставленных ОС событий с `kbSyntheticMarker`, точный текст `привет` и каретка в позиции 6. Продолжение `!` и Backspace также адресуются только собственному PID.

После выхода из callback копии событий, полученных нижним перехватчиком через ОС, превращаются в `NSEvent`. В `NSApplication.sendEvent` проверяются исходный маркер и PID. Затем сохраняются полученные символы, код клавиши, модификаторы, время и признак повтора, а номер окна связывается со скрытым полем. `NSTextView.keyDown` выполняет нативное редактирование. Без номера собственного окна AppKit вставляет Unicode, но игнорирует Backspace в скрытом окне. Минимальная проверка этого поведения сохранена в `11-transport-window-check.swift`. Поле находится в скрытом окне, приложение имеет политику активации `.prohibited`. Эта маршрутизация не подтверждает естественный выбор поля по фокусу. Физическая клавиатура, сторонние приложения, решение `Engine`, правила допуска и очередь токенов этой пробой не проверяются.

## Изоляция и ограничения

Тестовый bundle находится в `/private/tmp/Keyboop_transport.app`, имеет ID `ru.keyboop.app.transport` и имя `Keyboop Transport Check`. Проверка подписи обязательна перед запуском. Установленное приложение, его настройки и журнал остаются за пределами пробы. Если настоящий `EventTap` пишет диагностику, она попадает в отдельный `Keyboop-transport.log`.

Проверки AX и Input Monitoring не запрашивают разрешений. Реальное создание перехватчика определяет доступность пробы. Для каждой фазы ожидание ограничено двумя секундами, для процесса предусмотрен сторож на десять секунд и внешний предел на двенадцать секунд. Перехватчики отключаются, их источники удаляются из run loop, Mach-порты инвалидируются при штатном выходе и ошибке. При аварийном завершении процесса его порты освобождает ОС.

Верхний перехватчик сразу пропускает события, не совпавшие по PID, маркеру, типу и коду 255. Нижний перехватчик процесса пропускает все события, кроме собственной синтетики с точным маркером и PID. Глобальная проба не передаёт их в `EventTap.handle`. Проверка фильтра содержит пять утверждений, включая чужой PID, другой старший бит маркера, печатающий код и `keyUp`.

## Команды

```bash
bash scripts/test-neural-transport.sh gate
KEYBOOP_RELEASE=0 KEYBOOP_SIGN_ID=- KEYBOOP_BUILD_APP=/private/tmp/Keyboop_transport.app bash build-app.sh
/usr/libexec/PlistBuddy -c 'Set :CFBundleIdentifier ru.keyboop.app.transport' /private/tmp/Keyboop_transport.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Set :CFBundleDisplayName Keyboop Transport Check' /private/tmp/Keyboop_transport.app/Contents/Info.plist
codesign --force --sign - /private/tmp/Keyboop_transport.app
bash scripts/test-neural-transport.sh --os
bash scripts/test-neural-layout.sh assistance
bash scripts/test-layout-diagnostics.sh all
bash scripts/test-layout-detector.sh all
```

CoreML при сборке требует доступного временного каталога. Запуск настоящих CoreGraphics/AppKit-проб требует доступа к оконной сессии. В проверенной среде эти команды выполнялись вне файловой песочницы без изменения TCC.

## Результаты

Глобальный маркер дошёл через ОС в настоящий `EventTap.handle` с полными 64 битами и был поглощён. Проверка AX и Input Monitoring вернула `true`. Первая адресная проба вызвала настоящий `replaceInline` и отправила 14 событий, но естественная очередь скрытого фонового приложения не получила ни одного. Этот результат сохранён в `11-transport-inactive-queue.txt`. Окончательный запуск завершился с кодом 0. Нижний перехватчик ОС получил все 14 событий, явная маршрутизация AppKit дала `привет` и каретку в позиции 6. Продолжение `!` и Backspace сохранили точные текст и каретку. Файл `11-transport-startup-regression.txt` содержит причину стартового SIGTRAP в первой версии проверочного процесса. Исправление использует singleton подкласса `NSApplication`, подтверждённый отдельным минимальным воспроизведением. Этот сбой произошёл до отправки событий.
