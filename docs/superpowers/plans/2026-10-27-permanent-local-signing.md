# Постоянная локальная подпись Keyboop

Схема согласована Никой: один сертификат Keychain, постоянные bundle ID и путь установки. Сборка останавливается при недоступном сертификате, временная подпись не подставляется.

## План и проверка

- [x] Создать ключ непосредственно в Keychain и сертификат `Keyboop Local Dev` только для подписи кода. Закрытый ключ не экспортировать. Проверить назначение и срок публичного сертификата, наличие identity.
- [x] Вынести подпись в `scripts/sign-keyboop-app.sh`, подключить предварительную проверку и подпись к `build-app.sh`. Проверить отказ при отсутствии identity, запросе ad-hoc и ошибке вложенной или внешней подписи. Сохранить entitlements и порядок подписи вложенных компонентов.
- [x] Подписать два разных тестовых бинарника, подтвердить разные cdhash и одинаковые designated requirements, проверить оба бинарника по требованию первой подписи. Подписать отдельную копию готового Keyboop, проверить все компоненты и установить с резервной копией настроек и журнала.
- [x] Подтвердить окно установленной версии, зафиксировать состояние разрешений и обновить memora. После однократной выдачи доступов сохранение подтверждено на следующей полной сборке и установке: engine STARTED с AX=true и InputMon=true в 17:44:19 MSK.

## Принятые ограничения

Доверие сертификату задаётся только для code signing в пользовательской области. Другие сертификаты и разрешения приложений не меняются. DMG не обновляется. Две подписи подтверждают стабильность идентичности, но не заменяют проверку сохранения TCC на живом обновлении.
